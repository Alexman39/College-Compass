Η δεύτερη εβδομαδιαία αποστολή (Weekly Security Mission). Δεν βαθμολογείται,
αλλά εφαρμόζει στην πράξη όσα είδαμε για τα δέντρα επιθέσεων στην Εβδομάδα 2.

## 1. Εκφώνηση

> «Δημιουργήστε και αναλύστε ένα δέντρο επιθέσεων για την παρακάτω υποδομή.
> Διακρίνετε τα πιθανά από τα απίθανα σενάρια ανάλογα με το εκτιμώμενο κόστος
> και προτείνετε σχετικά αντίμετρα, αναφέροντας τυχόν παραδοχές που έχετε
> κάνει.»

![Διάγραμμα της υποδομής. Αριστερά τρεις είσοδοι προς ένα εξωτερικό firewall: το Cloud Mail Service μέσω VPN, το Internet, και ο Cloud Hosted Web Server μέσω VPN. Μετά το firewall ένας router, που συνδέεται με Honeypot, File Server, DB Server και FTP Server. Από τον router ένα δεύτερο, εσωτερικό firewall οδηγεί στο εσωτερικό δίκτυο: Client Machines, RADIUS Server και Directory Server.](./images/attack-tree-infrastructure.jpg)

Στο μάθημα ζητήθηκαν επιπλέον: ανάλυση της υποδομής, κατασκευή του attack
tree, εκτίμηση κόστους των επιθέσεων, υπολογισμός πιθανοτήτων, αξιολόγηση
κινδύνου, προτάσεις προστασίας, **επαναϋπολογισμός μετά τα αντίμετρα** και μια
**επαγγελματική αναφορά προς τη διοίκηση**.

## 2. Η υποδομή

| Στοιχείο | Ρόλος |
| --- | --- |
| Internet | εξωτερικό δίκτυο και πιθανή προέλευση επιθέσεων |
| Cloud Mail Service | εταιρικό email, συνδέεται μέσω VPN |
| Cloud Hosted Web Server | δημόσια ιστοσελίδα στο cloud, συνδέεται μέσω VPN |
| VPN | κρυπτογραφημένες συνδέσεις των υπηρεσιών cloud με την εταιρεία |
| Εξωτερικό firewall | έλεγχος της εισερχόμενης κίνησης |
| Router | δρομολόγηση προς τους servers και το εσωτερικό δίκτυο |
| Honeypot | σύστημα-δόλωμα που προσελκύει και καταγράφει επιτιθέμενους |
| File Server | εταιρικά αρχεία |
| DB Server | βάση δεδομένων |
| FTP Server | μεταφορά αρχείων |
| Εσωτερικό firewall | διαχωρίζει το εσωτερικό δίκτυο από τους servers |
| Client Machines | υπολογιστές των εργαζομένων |
| RADIUS Server | αυθεντικοποίηση (π.χ. για VPN και Wi-Fi) |
| Directory Server | χρήστες, ομάδες και δικαιώματα (π.χ. Active Directory) |

Το διάγραμμα **δεν** δείχνει κανόνες firewall, εκδόσεις λογισμικού ή
πραγματικές ευπάθειες. Ό,τι δεν είναι γνωστό το γράφεις ως **παραδοχή**.

> **Επεξήγηση:** Το honeypot δεν είναι στόχος με πραγματικά δεδομένα. Είναι
> κυρίως μηχανισμός **ανίχνευσης** και όχι απαραίτητα **αποτροπής**: δεν
> εμποδίζει την επίθεση, αλλά την αποκαλύπτει νωρίς και καταγράφει πώς κινείται
> ο επιτιθέμενος. Στο δέντρο σου μπορεί να εμφανιστεί ως **αντίμετρο
> ανίχνευσης**, όχι ως διαδρομή προς τα δεδομένα. Στον επαναϋπολογισμό
> (ενότητα 7) δεν μειώνει από μόνο του την πιθανότητα να πετύχει μια επίθεση·
> μειώνει τον χρόνο που ο επιτιθέμενος μένει απαρατήρητος, άρα και τη ζημιά.

## 3. Ο στόχος του επιτιθέμενου

Προτεινόμενη ρίζα: **«Μη εξουσιοδοτημένη πρόσβαση σε ευαίσθητα εταιρικά
δεδομένα»**.

Αυτός ο στόχος καλύπτει την παραβίαση λογαριασμών, την εκμετάλλευση servers,
την παραβίαση εσωτερικών υπολογιστών και τη φυσική πρόσβαση. Η διακοπή
υπηρεσιών (DoS/DDoS) είναι **άλλος** τελικός στόχος· αν θέλεις, ανάλυσέ τον σε
ξεχωριστό δέντρο.

## 4. Αρχική δομή του δέντρου

```text
ROOT [OR]: Μη εξουσιοδοτημένη πρόσβαση σε εταιρικά δεδομένα
├── A. Κλοπή διαπιστευτηρίων: phishing, κλεμμένοι κωδικοί, κατάχρηση VPN
├── B. Παραβίαση server: ευπάθεια στον Cloud Web Server, FTP, DB ή File Server
├── C. Παραβίαση εσωτερικού δικτύου: μολυσμένο endpoint, lateral movement
└── D. Φυσική πρόσβαση: σε σταθμό εργασίας ή εξοπλισμό
```

Αυτή είναι μόνο η αρχή. Κάθε κλάδος πρέπει να σπάσει σε κόμβους και φύλλα, με
σαφές **AND** ή **OR**. Για παράδειγμα, η παραβίαση του δημόσιου web server
**και** η πρόσβαση από εκεί στον εσωτερικό DB Server είναι διαδοχικά βήματα
(AND), όχι δύο ισοδύναμες επιλογές.

> **Προσοχή:** Το attack tree και η αξιολόγηση κινδύνου είναι **δύο
> διαφορετικά** πράγματα. Το δέντρο περιγράφει τις **διαδρομές** επίθεσης: πώς
> μπορεί κάποιος να φτάσει στον στόχο. Η αξιολόγηση κινδύνου (risk assessment,
> ενότητα 6.3) εκτιμά, για κάθε διαδρομή, **πόσο πιθανή** είναι και **τι ζημιά**
> θα προκαλούσε. Κράτησέ τα σε χωριστές ενότητες της αναφοράς.

## 5. Υπολογισμός πιθανοτήτων

Οι παρακάτω τύποι ισχύουν **μόνο με την παραδοχή ότι τα γεγονότα είναι
ανεξάρτητα**. Γράψε αυτή την παραδοχή ρητά στην αναφορά:

- **OR**: P = 1 − (1 − p₁) × (1 − p₂) × … × (1 − pₙ)
- **AND**: P = p₁ × p₂ × … × pₙ

**Υποθετικό παράδειγμα** με τρεις εναλλακτικές διαδρομές: κλοπή credentials
30%, εκμετάλλευση server 20%, παραβίαση endpoint 15%.

P = 1 − (0,70 × 0,80 × 0,85) = 1 − 0,476 = **0,524 (52,4%)**

Το 52,4% είναι η πιθανότητα να πετύχει **τουλάχιστον μία** διαδρομή μέσα σε
αυτό το υποθετικό μοντέλο. Δεν είναι από μόνο του η πραγματική ετήσια
πιθανότητα παραβίασης: γι' αυτήν χρειάζεσαι σαφή ορισμό των γεγονότων, χρονικό
ορίζοντα και συχνότητα επιθέσεων.

### Διαδοχικά στάδια: δεσμευμένες πιθανότητες

Σε μια επίθεση με **διαδοχικά** στάδια, το δεύτερο βήμα συχνά εξαρτάται από το
πρώτο: η πρόσβαση στον DB Server είναι πολύ πιο εύκολη **αφού** έχει ήδη
παραβιαστεί ο web server. Τότε, αντί για απλό γινόμενο, χρησιμοποιείς τη
**δεσμευμένη πιθανότητα** `$P(B \mid A)$`, δηλαδή την πιθανότητα του B **δεδομένου**
ότι έχει συμβεί το A:

```math
P(A \text{ AND } B) = P(A) \cdot P(B \mid A)
```

**Υποθετικό παράδειγμα:** παραβίαση του web server `$P(A) = 0{,}20$`· πρόσβαση στον
DB Server από τον παραβιασμένο web server `$P(B \mid A) = 0{,}40$`. Τότε
`$P = 0{,}20 \cdot 0{,}40 = 0{,}08$` (8%). Αν τα δύο γεγονότα ήταν ανεξάρτητα, θα
ίσχυε `$P(B \mid A) = P(B)$` και ο τύπος θα γινόταν ο απλός τύπος του AND.

## 6. Κόστος επίθεσης, πιθανή ζημιά και αξιολόγηση κινδύνου

Δύο «κόστη» που **δεν** πρέπει να μπερδεύονται: το **κόστος της επίθεσης**,
δηλαδή τι χρειάζεται ο επιτιθέμενος για να την κάνει, και η **πιθανή ζημιά**
της εταιρείας αν η επίθεση πετύχει. Ένα φθηνό σενάριο για τον επιτιθέμενο, όπως
ένα phishing, μπορεί να είναι πολύ ακριβό για την εταιρεία.

### 6.1 Κόστος για τον επιτιθέμενο

Ενδεικτικές ποιοτικές εκτιμήσεις (όχι τεκμηριωμένα πραγματικά κόστη):

| Επίθεση | Κόστος | Δυσκολία |
| --- | --- | --- |
| Phishing | χαμηλό | χαμηλή |
| Επίθεση σε κωδικούς | χαμηλό – μεσαίο | μεσαία |
| Εκμετάλλευση **γνωστής** ευπάθειας | χαμηλό – μεσαίο | μεσαία |
| Εκμετάλλευση **άγνωστης** ευπάθειας (zero-day) | πολύ υψηλό | υψηλή |
| Φυσική πρόσβαση | μεταβλητό | μεσαία – υψηλή |

Στο τελικό δέντρο χρειάζονται **αιτιολογημένες** αριθμητικές τιμές ή εύρη. Όπως
στο παράδειγμα του χρηματοκιβωτίου: σε κόμβο **OR** κρατάς τη **φθηνότερη**
επιλογή· σε κόμβο **AND** **αθροίζεις** τα κόστη (με την παραδοχή ότι
προστίθενται). Έτσι ξεχωρίζεις τα **πιθανά** σενάρια (φθηνά, εύκολα) από τα
**απίθανα** (ακριβά, δύσκολα), όπως ζητά η εκφώνηση.

### 6.2 Πιθανή ζημιά για την εταιρεία (impact)

Η επίπτωση εξαρτάται από **τι** χάνεται, όχι από το πόσο δύσκολη ήταν η
επίθεση. Ενδεικτικές ποιοτικές εκτιμήσεις:

| Αν πετύχει… | Επίπτωση | Γιατί |
| --- | --- | --- |
| Διαρροή του DB Server | υψηλή | προσωπικά δεδομένα: πρόστιμα (GDPR), αποζημιώσεις, φήμη |
| Παραβίαση του Directory Server | πολύ υψηλή | ελέγχει χρήστες και δικαιώματα όλου του δικτύου |
| Αλλοίωση του Cloud Web Server | μεσαία | φήμη και διακοπή της δημόσιας ιστοσελίδας |
| Παραβίαση ενός client | χαμηλή – μεσαία | μικρή, αν δεν ακολουθήσει lateral movement |

Αν δώσεις χρηματικά ποσά, αιτιολόγησέ τα (π.χ. αριθμός εγγραφών, κόστος
διακοπής ανά ώρα) και δήλωσέ τα ως εκτιμήσεις.

### 6.3 Αξιολόγηση κινδύνου: Risk Matrix

Ο κίνδυνος συνδυάζει την **πιθανότητα** (ενότητα 5) με την **επίπτωση**
(ενότητα 6.2). Ένας απλός πίνακας Likelihood × Impact κάνει την ιεράρχηση
ορατή με μια ματιά:

| Πιθανότητα ↓ / Επίπτωση → | Χαμηλή | Μεσαία | Υψηλή |
| --- | --- | --- | --- |
| **Υψηλή** | μεσαίος | υψηλός | **κρίσιμος** |
| **Μεσαία** | χαμηλός | μεσαίος | υψηλός |
| **Χαμηλή** | χαμηλός | χαμηλός | μεσαίος |

Τοποθέτησε κάθε κλάδο ή σενάριο του δέντρου σε ένα κελί και ξεκίνα τα
αντίμετρα από τα κρίσιμα και τα υψηλά. Για παράδειγμα, στο υποθετικό μοντέλο
της ενότητας 5, η κλοπή credentials (30%) που οδηγεί σε διαρροή του DB Server
(υψηλή επίπτωση) θα έπεφτε στο «υψηλός» ή «κρίσιμος», ανάλογα με το πού
ορίζεις τα όρια της πιθανότητας. Γράψε στην αναφορά ποια όρια χρησιμοποίησες
(π.χ. χαμηλή κάτω από 10%, υψηλή πάνω από 30%).

## 7. Αντίμετρα και επαναϋπολογισμός

| Απειλή | Αντίμετρα |
| --- | --- |
| Κλοπή κωδικών | MFA, εκπαίδευση για το phishing |
| Παραβίαση VPN | MFA, ενημερώσεις, περιορισμός πρόσβασης |
| Ευάλωτος web server | patching, WAF, ασφαλής παραμετροποίηση |
| FTP χωρίς κρυπτογράφηση | SFTP όπου ενδείκνυται |
| Lateral movement | διαχωρισμός δικτύου (segmentation), περιορισμένα δικαιώματα |
| Παραβίαση endpoints | EDR, ενημερώσεις, application control |
| Μη εξουσιοδοτημένη πρόσβαση | least privilege, παρακολούθηση (monitoring), έλεγχοι ταυτότητας |
| Επιτιθέμενος που ήδη κινείται στο δίκτυο | το honeypot για έγκαιρη **ανίχνευση** (όχι αποτροπή), μαζί με καταγραφή και ειδοποιήσεις |

Μετά τα αντίμετρα, **ξαναϋπολόγισε** τον κίνδυνο. Αν στο παράδειγμα της
ενότητας 5 οι τρεις διαδρομές πέσουν από 30%, 20%, 15% σε 5%, 6%, 4%:

P<sub>μετά</sub> = 1 − (0,95 × 0,94 × 0,96) = 1 − 0,85728 = **0,14272 (≈14,3%)**

Πριν: 52,4%. Μετά: περίπου 14,3%. Είναι **υποθετικό** παράδειγμα, όχι
μετρημένη αποτελεσματικότητα. Κάθε μείωση πιθανότητας θέλει αιτιολόγηση.

## 8. Δομή της αναφοράς

1. **Executive Summary**: οι βασικοί κίνδυνοι και τα συμπεράσματα.
2. **Infrastructure Overview**: περιγραφή του δικτύου.
3. **Scope & Assumptions**: όρια και παραδοχές.
4. **Threat Identification**: απειλές και ευπάθειες.
5. **Attack Tree**: οι διαδρομές επίθεσης, το διάγραμμα και η εξήγησή του.
6. **Cost Analysis**: κόστος και δυσκολία για τον επιτιθέμενο.
7. **Probability Analysis**: τύποι, παραδοχή ανεξαρτησίας και υπολογισμοί.
8. **Risk Evaluation**: πιθανή ζημιά (impact), Risk Matrix και ιεράρχηση των
   κινδύνων.
9. **Security Recommendations**: αντίμετρα.
10. **Residual Risk Analysis**: ο κίνδυνος μετά τα αντίμετρα.
11. **Conclusion**: συμπεράσματα και προτεραιότητες.
12. **References**: πηγές.

Η αναφορά γράφεται **στα ελληνικά**· οι τίτλοι των ενοτήτων μπορούν να μείνουν
όπως είναι.

## 10. Προσοχή σε αυτά

1. Το ότι ένα σύστημα υπάρχει στο διάγραμμα **δεν** αποδεικνύει ότι έχει
   ευπάθεια. Ό,τι δεν είναι επιβεβαιωμένο το δηλώνεις ως παραδοχή.
2. Η πιθανότητα να **πετύχει** μια επίθεση υπό συγκεκριμένες συνθήκες είναι
   άλλο πράγμα από την πιθανότητα να **δεχτεί** επίθεση η εταιρεία σε μια
   περίοδο.
3. Μη μειώνεις τις πιθανότητες μετά τα αντίμετρα αυθαίρετα· αιτιολόγησε κάθε
   αλλαγή και ανέφερε την αβεβαιότητα.
4. Οι τύποι AND/OR υποθέτουν **ανεξαρτησία**· στην πράξη οι διαδρομές συχνά
   εξαρτώνται η μία από την άλλη (π.χ. ένα πετυχημένο phishing διευκολύνει το
   lateral movement). Για διαδοχικά στάδια χρησιμοποίησε δεσμευμένες
   πιθανότητες (ενότητα 5).
5. Το κόστος μιας επίθεσης για τον επιτιθέμενο είναι άλλο από τη ζημιά της
   εταιρείας. Μην τα αθροίζεις και μην τα συγκρίνεις σαν να ήταν το ίδιο μέγεθος.
6. Πρόκειται για ανάλυση σε **υποθετική** υποδομή, με τεκμηριωμένες
   εκτιμήσεις, όχι για μέτρηση ενός πραγματικού δικτύου.
